Website demo – Ripe or Not

A walk through the live web app, top to bottom, with what to click and what to say.

about 8–10 minutes live: huggingface.co/spaces/AD074890/ripe-or-not backup: python webapp/server.py → 127.0.0.1:8000

Before you start 5 min before

DO Open the live demo and click one sample photo once, so the ~90 MB model download is done before the audience is watching. The next predictions take under a second.
DO Keep a second tab with the presentation (presentation.html) and a third with the GitHub repo.
IF NO INTERNET Run python webapp/server.py and open http://127.0.0.1:8000. It is the same page, served from your laptop.

1 · Opening 0:00 – 1:00

SHOW The top of the page: “Ripe or not?” and the empty “Try it” board.

Good morning. My project is fruit ripeness grading using ordinal regression.

The question is simple: given a photo of a strawberry or an avocado, how ripe is it? We use four stages: unripe, partially ripe, ripe and rotten.

The key point of the project is that these four stages are ordered. Rotten comes after ripe, and ripe comes after partially ripe. So the model should be punished more for being three steps wrong than for being one step wrong. That is what ordinal regression does, and I will show it live.

2 · Live prediction 1:00 – 3:30

CLICK The rotten avocado sample (top row, last photo).

These small photos are from the test set. The model that answers never saw them during training. The label in the corner of the board says which model answered.

Look at the ripeness ruler. The arrow slides to the model's ripeness score, here about 3, which is rotten, and that matches the true grade.

POINT At the three coloured sticky notes.

This is how the ordinal model thinks. It does not pick one of four boxes. It answers three yes/no questions: is the grade above 0? above 1? above 2? Here all three answers are “yes”, so the grade is 3.

The grade is simply the number of yes answers. All three questions share one ripeness score, so the answers can never contradict each other.

POINT At the Grad-CAM photo and the yellow note.

On the left is Grad-CAM. It shows which part of the image pushed the model towards “more ripe”. Here it lights up the dark, wrinkled skin, which is exactly the evidence a person would use.

The yellow note shows a normal softmax classifier trained the same way, for comparison.

CLICK One more sample, for example the green unripe avocado or the pale strawberry. If the model is wrong, say so.

When the model is wrong, the page says how far off it is. Most mistakes are only one grade off, and that is the kind of mistake ordinal regression tries to keep.

OPTIONAL Drag your own fruit photo onto the green note. Uploaded photos are graded by the same model, running inside the browser.

3 · “Order matters” 3:30 – 4:30

SCROLL To “Order matters”.

On the left: softmax sees four unrelated boxes. Calling a rotten fruit unripe costs the same as calling it ripe.

On the right: the cumulative targets. A ripe fruit, grade 2, is encoded as yes, yes, no. Being three grades off breaks three answers; being one grade off breaks only one. So the loss itself understands distance.

The formula underneath is the CORAL method: one shared score, three thresholds, and binary cross-entropy summed over the three questions.

4 · Pipeline 4:30 – 6:00

SCROLL To “From photo to grade”. The dashed arrows draw themselves.

Data: 758 real photos from a published dataset, labelled with YOLO bounding boxes. I cropped every box and got 924 single-fruit images. That uses the bounding-box part of Unit IV.

Leak-free folds: the dataset has burst shots and edited copies of the same fruit. If one copy is in training and its twin is in testing, the score is fake. So I grouped them and used 5-fold grouped cross-validation. Every image is tested exactly once, by a model that never saw it.

Augmentation: crops, flips, rotation and lighting, but never hue, because colour is the label.

ResNet18 pretrained on ImageNet. First the backbone is frozen for 3 epochs, then everything is unfrozen with a 10× smaller learning rate for the backbone. That is Unit III, transfer learning.

Then the ordinal head, and finally the grade plus Grad-CAM.

5 · Results 6:00 – 8:00

SCROLL To “What the numbers say”. The numbers count up.

I compared three models under identical conditions: same folds, same seeds, same schedule. Three models, five folds, three seeds: 45 training runs.

The main metric is MAE, the average number of grades the model is off by.

The small CNN from scratch: 0.42. ResNet18 with softmax: 0.23. ResNet18 with the ordinal head: 0.21.

So transfer learning roughly halves the error. The ordinal head is ahead of softmax on every metric: accuracy 79.5% vs 79.0%, QWK 0.924 vs 0.910, and severe mistakes, two or more grades off, 0.79% vs 1.37%.

To be honest about it: the gaps are about one standard deviation across seeds. So it is a consistent small edge, not a proven win. The clearest benefit is fewer big mistakes, which is what ordinal regression is designed for.

POINT At “How wrong are the wrong answers?”, then switch the confusion-matrix menu between models.

The bars show how far off the wrong answers are. In the confusion matrix, a good model keeps its mistakes next to the diagonal. The scratch CNN spreads them much further.

6 · Grad-CAM and close 8:00 – 9:30

SCROLL To “Where does it look?”.

One test photo per fruit and stage. For ripe and rotten fruit, the heat sits on the skin, the mould and the red flesh, which is the right evidence.

For unripe fruit there is little “riper” evidence, so the map drifts to the background. That is a real weakness, and I report it.

Likely questions Q & A

Why not just use regression and predict a number?
Plain regression assumes the stages are equally spaced, which they are not. CORAL keeps the order but learns its own thresholds between stages.
Why is the website fast with no server?
The trained model was converted to ONNX and runs inside the browser with ONNX Runtime Web. Hugging Face only stores the files. I checked that the browser gives the same grade as PyTorch on all 8 sample photos.
How did you avoid data leakage?
I grouped crops from the same photo, burst shots with nearby photo numbers, and near-duplicate crops by perceptual hash. Then I split by group with StratifiedGroupKFold, so no group appears in two folds.
Is the ordinal model really better?
It is better on average on every metric and more stable across seeds, but the gap is about one standard deviation. The strongest effect is on severe errors.
What would you do next?
More photo sessions per class (most rotten strawberries come from one session), a detect-then-grade pipeline with YOLO for photos with many fruits, and calibrated thresholds.
How is Grad-CAM computed in the browser?
For the ordinal score s = w · GAP(A), the gradient with respect to each map is w/49, so Grad-CAM reduces to ReLU(Σ w·A). It is computed in the forward pass and matches the PyTorch version to within 1e-5.
