Step 0 · The problem and the idea

Input: one photo of a fruit (strawberry or avocado). Output: a ripeness grade.

Grade0123
Stageunripepartially riperiperotten

The grades are ordered. A normal softmax classifier treats them as unrelated labels: predicting "unripe" for a rotten fruit costs the same as predicting "ripe". Ordinal regression uses the order, so far-off mistakes are penalised more and become rarer. The project tests whether that helps, against a fair softmax baseline.

Environment: Python 3.14, PyTorch 2.14 + torchvision 0.29, NVIDIA RTX 3050 laptop GPU (4 GB).

Step 2 · Cropping and a leak-free split Unit IV

2a. Cropping (src/prepare_data.py)

Each YOLO box is converted to pixel corners, grown by an 8% border, and cut out. Result: 924 crops, one fruit each. This turns a detection dataset into a classification dataset.

x1 = (cx − w/2)·W,  y1 = (cy − h/2)·H,  x2 = (cx + w/2)·W,  y2 = (cy + h/2)·H

2b. Why a careful split matters: data leakage

Many photos are near-copies (burst shots, the same fruit pasted onto different backgrounds). If one copy lands in training and another in test, the model is tested on something it has already seen, and the score is inflated. That is data leakage.

Fix: put near-copies into one group, and keep each group inside one split. Two crops join the same group if:

  1. they come from the same source photo, or
  2. they have the same class and photo numbers in the same block of 10 (burst shots), or
  3. their perceptual hash (a tiny fingerprint of the image centre) differs by ≤ 40 bits.

Result: 159 groups. Two earlier rules were tried and rejected: one merged 93 different avocados into one group (too loose); another could not separate true burst pairs from different fruits.

2c. 5-fold grouped cross-validation

A single 70/15/15 split left only 2 ripe avocados in test, too few to measure. So the data is cut into 5 folds (whole groups only). For run k: test on fold k, validate (for early stopping) on fold k+1, train on the other 3. Every crop is tested exactly once, and results are pooled. A check confirms no group appears in two folds.

Known limitation: most rotten strawberries come from one shooting session, so they sit in one fold. When that fold is the test fold, training sees few rotten strawberries. This makes scores harder, not inflated.

Step 4 · The three models Unit II Unit III

Model A · small CNN from scratch (baseline)

4 blocks of [conv → BatchNorm → ReLU] ×2 + max-pool, then global average pooling, dropout 0.3, and a linear layer with 4 outputs + softmax. Shows what a network learns with no prior knowledge.

Model B · ResNet18 + softmax (transfer learning)

ResNet18 pretrained on ImageNet (1.28 M images, 1,000 classes). Its 1,000-class final layer is replaced by a linear layer with 4 outputs. Loss: cross-entropy L = −log ptrue.

Why ResNet18: residual (skip) connections y = F(x) + x let gradients flow through deep networks; ~11 M parameters fits 4 GB GPU memory with batch 32 and mixed precision (AMP).

Model C · ResNet18 + ordinal head (CORAL)

Same backbone. The head answers K−1 = 3 yes/no questions instead of picking 1 of 4 classes:

Questiongrade 0grade 1grade 2grade 3
grade > 0 ?0111
grade > 1 ?0011
grade > 2 ?0001
s       = w · features                  (one shared "ripeness score")
logit_k = s + b_k        k = 0, 1, 2     (3 learned thresholds)
p_k     = sigmoid(logit_k)               = P(grade > k)
loss    = Σ_k  BCE(p_k, target_k)
grade   = number of p_k above 0.5

Rank consistency: because all three questions share one score s and the thresholds are ordered, P(>2) ≤ P(>1) ≤ P(>0) always holds. The answers can never contradict each other. Reference: Cao, Mirjalili & Raschka (2020), "Rank consistent ordinal regression for neural networks".

Fair comparison: B and C differ only in the head and loss. Same backbone, data folds, augmentation, optimiser, schedule and seeds.

Bug found by the overfit test: the first ordinal model got stuck at loss 0.47. Cause: the 3 thresholds started only 0.33 apart and Adam moves each one by about one learning-rate step per update, so they could not spread out. Fix: start them at [2, 0, −2] and give them a 10× learning rate. After the fix the loss kept falling.

Step 8 · Grad-CAM interpretability Unit VI

Grad-CAM shows which image regions drove the prediction. Written by hand with PyTorch hooks on ResNet18's last convolution block (layer4):

  1. Forward pass; save the feature maps Ak of layer4 (512 maps of 7×7).
  2. Backward pass from the target score; save the gradients ∂score/∂Ak.
  3. Weight of each map: αk = average of its gradient.
  4. Heatmap = ReLU(Σk αk·Ak), upsampled to 224×224 and overlaid on the image.

For the ordinal model the target is the shared ripeness score s, so red means "evidence for riper".

Findings: for ripe and rotten fruit the heat sits on the fruit surface (dark skin, mould, red flesh): the model looks at the right thing. For unripe fruit the heat drifts to corners or a neighbouring red fruit, because an unripe fruit holds no "riper" evidence. This exposes a real weakness: background and neighbouring fruit can influence the grade. Unripe vs partially ripe avocado is the hardest pair (both green).

Step 9 · Web app (final stage)

An interactive web app in the style of the presentation template: the user uploads a fruit photo, the trained model returns the grade, the three threshold probabilities and a Grad-CAM heatmap, with motion graphics.

Likely viva questions

Why ordinal regression instead of softmax? Grades are ordered. Softmax ignores order, so all mistakes cost the same. The ordinal head makes far-off mistakes rarer.
Why K−1 outputs? 4 grades need 3 thresholds between them: >0, >1, >2.
Why share the weight vector? One score + ordered thresholds guarantees consistent answers (rank consistency).
Why group the split? Near-duplicate photos in train and test leak information and inflate scores.
Why freeze the backbone first? The random new head sends large gradients that would destroy pretrained features.
Why no colour augmentation? Colour is the ripeness signal.
Why is the starting loss 1.386? A model that knows nothing gives each of 4 classes p = 0.25, and −ln 0.25 = ln 4.
Why MAE as the main metric? It measures how far off a prediction is, which is what ordinal grading cares about.
